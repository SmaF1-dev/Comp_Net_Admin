# Примеры LogQL-запросов

## Проверено на стенде

Все записи Nextcloud:

```logql
{job="nextcloud_logs"}
```

Этот запрос вернул пять исходных записей в разделе выполнения запросов Grafana (см. `screenshots/11-grafana-loki.png`).

Фильтрация диагностических записей по подстроке:

```logql
{job="nextcloud_logs"} |= "LAB2_PIPELINE_"
```

Оператор `|=` оставляет строки, содержащие заданную подстроку. Запрос вернул одну запись с маркером `LAB2_PIPELINE_1d7f9a65f7ab` (см. `screenshots/15-logql-filter.png`).

## Дополнительные примеры

Записи со словом `error` (поиск чувствителен к регистру):

```logql
{job="nextcloud_logs"} |= "error"
```

Поиск сообщений о входе в систему:

```logql
{job="nextcloud_logs"} |~ "(?i)login"
```

Число записей за пять минут по потокам:

```logql
count_over_time({job="nextcloud_logs"}[5m])
```

Суммарное число записей за пять минут:

```logql
sum(count_over_time({job="nextcloud_logs"}[5m]))
```

Эти четыре запроса приведены для самостоятельных экспериментов; их результаты отдельно не проверялись и не фиксировались. Временной диапазон Grafana должен охватывать моменты создания записей. Пустой результат фильтра не обязательно означает неисправность сборщика: совпадений может не быть.
